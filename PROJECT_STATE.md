### Architectural Decisions

- **No database or state management library** — constraint from T1 spec.
- **`@nuxt/eslint`** — official Nuxt ESLint integration; generates config from `.nuxt/eslint.config.mjs` after `nuxt prepare`.
- **`@nuxtjs/tailwindcss`** — official Nuxt module; zero-config CSS generation.
- **Vitest with globals** — avoids importing `describe`/`it`/`expect` in every test file, standard for Nuxt projects.
- **Unit test targets a pure TS utility** — avoids needing Vue testing utilities or DOM environment for T1.
- **`vue-tsc`** — required by `nuxt typecheck`; added during validation (was missing from initial spec).

### Limitations

- ESLint config imports from `.nuxt/eslint.config.mjs`, which only exists after `nuxt prepare` or `nuxt build`. Running `npm run lint` before install+prepare will fail.
- TypeScript path resolution depends on `.nuxt/tsconfig.json` generated by Nuxt at runtime.
